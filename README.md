# Starfield 리뷰어는 누가, 얼마나, 언제, 무엇에 실망하는가

Steam 리뷰 **175,300건**과 리뷰어 **업적(플레이 진행) 데이터**를 결합해, 평가가 갈리는 게임에서 어떤 유형의 유저가 언제·무엇에 실망하는지 분석했습니다.
리뷰 텍스트는 다국어 임베딩으로 "추천확률"이라는 연속 점수로 바꾸고, 플레이 행동으로 유저를 세 유형으로 나눈 뒤 둘을 결합했습니다.

- 기간: 2026.09 – 2026.10 (아이티윌 빅데이터 분석 과정 56기 파이널 프로젝트, 2인 팀)
- 발표 자료: [`docs/발표자료_Starfield_리뷰분석.pdf`](docs/발표자료_Starfield_리뷰분석.pdf) (42p)
- 계획 보고서: [`docs/계획보고서.md`](docs/계획보고서.md)

## 핵심 결과

| 질문 | 답 |
|---|---|
| 리뷰 텍스트만으로 추천/비추천을 맞힐 수 있나 | 5-fold out-of-fold **AUC 0.954 · 정확도 0.887** (길이만 쓴 기준선 AUC 0.574). 예측확률이 구간별 실제 추천 비율과 일치해 연속 점수로 사용 |
| 플레이 행동으로 리뷰어를 나눌 수 있나 | K-Means(k=3): **초기 리뷰어** 29% (8h·업적 3개 시점에 리뷰) · **하드 리뷰어** 37% (보유 게임 431·리뷰 29편·55h) · **라이트 리뷰어** 34% (보유 124·리뷰 5편·54h) |
| 누가, 언제 실망했나 | 추천확률 평균 라이트 0.64 > 하드 0.57 > 초기 0.51. 하드·초기 리뷰어는 메인 퀘스트 1단계 리뷰가 가장 부정적. 추천확률 0.3 미만 리뷰어의 절반은 리뷰 후 **1.7시간** 안에 그만둠 (0.7 이상은 41시간 더 플레이) |
| 무엇에 실망했나 | 부정 리뷰 20,924건 → 토픽 10개. 콘텐츠 불만(72%)은 유형과 무관, 차이는 기술·운영 불만에서: 초기 = **성능·최적화 14%**(전체의 2배), 하드 = 유료 모드·DLC, 라이트 = 버그·크래시. 성능 불만은 초반 19% → 완주 3% |

**시사점**: 가장 부정적인 집단(초기 리뷰어)은 8시간·1단계에서 리뷰를 쓰고 절반은 곧 떠나며, 그 불만의 핵심은 성능·최적화 → 초반 최적화가 평가와 잔존을 함께 결정.
텍스트는 긍정인데 비추천을 누른 초기 리뷰어(3.5%)는 리뷰 후 플레이가 길어 되돌릴 여지가 가장 큰 집단.

**한계**: 업적 비공개 리뷰어(59%) 제외로 인한 표본 편향 · 언어별 모델 성능 격차(AUC 0.86–0.98) · 콘텐츠 토픽은 경계가 흐려 이름이 근사치(실루엣 0.04) · 관찰 데이터의 상관이지 인과가 아님.

## 방법 요약

```
Steam 리뷰 API ──┐
                 ├─ 리뷰 + 리뷰 시점 진행 단계(업적) ─ 품질 점검 ─ 70,915명
Steam 업적 API ──┘                                        │
          ┌────────────────────────────────────────────────┤
          ▼                                                ▼
 ⑤ 리뷰 텍스트 → multilingual-e5-large 임베딩        ⑥ 플레이 변수 4개 → 로그·표준화 → K-Means
    → 로지스틱 회귀 → 추천확률 (0–1)                     → 페르소나 3개
          └───────────────────┬────────────────────────────┘
                              ▼
            ⑦ 유형 × 추천확률 (누가·얼마나·언제·그 뒤)
            ⑧ 부정 리뷰 임베딩 군집 + c-TF-IDF → 불만 토픽 (무엇에)
```

검증에서 신경 쓴 것
- 같은 텍스트("good", "10/10")가 학습·평가 양쪽에 들어가지 않도록 **중복 텍스트 격리 분할**, 전체 리뷰는 **out-of-fold**로 채점
- 예측확률 구간별 실제 추천 비율로 **보정 확인** 후 연속 점수로 사용
- 토픽 군집 전에 임베딩에서 **언어·길이 성분을 회귀 잔차로 제거** (보정 전엔 토픽이 아니라 언어로 갈림: 언어 예측 정확도 0.96 → 0.75)
- 29개 언어 전량 사용 (영어만 쓰면 40%가 빠지고, 빠지는 쪽의 긍정률이 다름)

## 재현

```bash
pip install -r requirements.txt
```

- 원본 데이터(리뷰 143MB, 업적 100MB, 임베딩 npz)는 용량 때문에 저장소에 없습니다. `01`과 `05a`를 실행하면 다시 만들 수 있고, `01`은 Steam Web API 키가 필요합니다(실행 시 입력, 코드에 남지 않음).
- 분석 산출물 세 개(`dataSets/추천확률.csv`, `유저군집.csv`, `불만토픽_v2.csv`)는 포함돼 있어 `07`·`08`의 결과 표는 바로 재현됩니다.
- 추천확률 재현에는 scikit-learn ≥ 1.8 이 필요합니다.

## 역할

- 김민재: 분석 대상 선정·선행연구, 수집 파이프라인, 품질 점검·EDA, 추천확률 모델(05), 유저 군집(06), 불만 토픽(08), 결론·한계
- 최용준: 유형 × 추천확률 종합분석(07)
